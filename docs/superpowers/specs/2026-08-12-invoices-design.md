# Invoices & Invoice Rows — Design

## Purpose

Add an invoices registry (anagrafica fatture) with per-invoice line items (invoice rows), following the existing Customer/Country CRUD pattern (UUID PKs, Inertia + Vue pages, resource controllers).

## Scope

Full CRUD with UI: migrations, models, factories, controller, form requests, routes, Vue pages (index/create/edit), sidebar nav entry, and feature tests. No seed data is added to `DatabaseSeeder` — this spec covers the registry itself, not demo data.

## Database schema

### `invoices`

| Column | Type | Notes |
|---|---|---|
| id | uuid, PK | |
| number | string, unique | e.g. `2026-0001`; auto-generated by default, editable afterward |
| invoice_date | date | |
| paid | boolean, default `false` | |
| customer_id | uuid FK → `customers.id`, NOT NULL, `restrictOnDelete` | a customer with invoices cannot be deleted |
| note | text, nullable | |
| timestamps | | |

### `invoice_rows`

| Column | Type | Notes |
|---|---|---|
| id | uuid, PK | |
| invoice_id | uuid FK → `invoices.id`, NOT NULL, `cascadeOnDelete` | deleting an invoice deletes its rows |
| description | string | free-text product/service description |
| price | decimal(10,2) | |
| vat_rate | decimal(5,2) | e.g. `22.00` |
| timestamps | | |

No `quantity` column (explicitly out of scope — one price per row). No `products` table (descriptions are free text, no separate product registry). No stored total column on either table — totals are computed accessors.

## Numbering logic

On `Invoice::creating`, if `number` is not explicitly set:

1. `$year = now()->format('Y')`
2. Find the invoice with the highest `number` matching `{$year}-%`.
3. Parse the trailing sequence from that number, `+1` (or `1` if none exists for that year).
4. Format as `sprintf('%s-%04d', $year, $seq)` → `2026-0001`, `2026-0002`, …

The sequence resets every calendar year. This lives in `Invoice::booted()`'s `creating` closure — no separate service/action class needed given current app size. The field remains freely editable after creation (`unique` validation enforced on store/update via the form requests, excluding the current row on update). No locking/race-condition handling — acceptable for this app's scale.

## Models

### `App\Models\Invoice`

- Traits: `HasUuids`, `HasFactory`.
- `#[Fillable(['number', 'invoice_date', 'paid', 'customer_id', 'note'])]`
- Casts: `invoice_date` → `date`, `paid` → `boolean`.
- `customer(): BelongsTo<Customer, $this>`
- `rows(): HasMany<InvoiceRow, $this>`
- Accessors (not persisted): `subtotal()` (sum of row prices), `vatTotal()` (sum of row VAT amounts), `total()` (subtotal + vatTotal).
- `booted()` registers the `creating` numbering logic described above.

### `App\Models\InvoiceRow`

- Traits: `HasUuids`, `HasFactory`.
- `#[Fillable(['invoice_id', 'description', 'price', 'vat_rate'])]`
- Casts: `price` → `decimal:2`, `vat_rate` → `decimal:2`.
- `invoice(): BelongsTo<Invoice, $this>`
- Accessor `total()` = `price + price * vat_rate / 100`.

## Controller & routes

`App\Http\Controllers\InvoiceController`, mirroring `CustomerController`:

- `index(Request $request)`: search by invoice number or customer name, eager-loads `customer`, paginated, `Inertia::render('invoices/Index', ...)`.
- `create()`: passes the list of customers and a server-generated default `number` for display.
- `store(StoreInvoiceRequest $request)`: creates the invoice and its rows inside a DB transaction.
- `edit(Invoice $invoice)`: loads the invoice with `rows` and `customer`.
- `update(UpdateInvoiceRequest $request, Invoice $invoice)`: updates invoice attributes and **syncs** rows — rows with a matching `id` are updated, existing rows whose `id` is no longer present are deleted, rows without an `id` are created. Wrapped in a DB transaction.
- `destroy(Invoice $invoice)`: deletes the invoice; rows cascade.

`routes/invoices.php`: `Route::resource('invoices', InvoiceController::class)->except('show')`, required from `routes/web.php` alongside `countries.php`/`customers.php`.

### Form requests

`StoreInvoiceRequest`:
```
number      => nullable|string|max:20|unique:invoices,number
invoice_date => required|date
paid        => boolean
customer_id => required|uuid|exists:customers,id
note        => nullable|string
rows            => required|array|min:1
rows.*.description => required|string|max:255
rows.*.price        => required|numeric|min:0
rows.*.vat_rate      => required|numeric|min:0|max:100
```

`UpdateInvoiceRequest`: same, plus `number` unique rule ignores the current invoice, and `rows.*.id => nullable|uuid|exists:invoice_rows,id` to identify existing rows during the sync.

## Frontend (Vue/Inertia)

`resources/js/pages/invoices/{Index,Create,Edit}.vue`, matching the Customers pages' structure and English UI text.

- **Index**: table with number, date, customer name, paid badge, computed total (`invoice.total` from the accessor), search box, "New invoice" button, Edit link — mirrors `customers/Index.vue`.
- **Create/Edit**: rows are a dynamic, repeatable list, which the static `<Form>` component (used for Customer's flat fields) doesn't support well. These two pages use Inertia's `useForm()` composable instead, with reactive `rows: []` array management (push/splice for add/remove) submitted as nested form data. Fields: `number` (prefilled with the server-generated default on Create, always editable), `invoice_date`, `paid` (checkbox), `customer_id` (select, same pattern as Customer's country select), `note` (textarea), and a rows table (description / price / VAT % inputs per row, add/remove row buttons, a live client-side running total for immediate feedback).
- `AppSidebar.vue`: add an "Invoices" nav entry (after Customers) using a `Receipt` icon from `@lucide/vue`.

## Testing

- Feature tests for `InvoiceController`: index (search/pagination), create, store (with rows), edit, update (including row sync: add/remove/edit rows), destroy (rows cascade), and validation failures.
- A focused test for the numbering logic: first invoice of a year → `2026-0001`; subsequent invoices increment; a new calendar year resets to `0001`; an explicitly-provided `number` is respected instead of being auto-generated.
- `InvoiceFactory` (customer via `Customer::factory()`, `number` left null so the model generates it, fake date/paid/note) and `InvoiceRowFactory` (fake description, price, vat_rate from `[22, 10, 4, 0]`) for use in tests.

## Out of scope

- Row quantity (single price per row only).
- A separate products/services registry.
- PDF generation / printing / sending invoices.
- Seed data in `DatabaseSeeder`.
- Locking against concurrent number-generation races.
