# NativePHP Desktop Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Package Biglins as a standalone, single-user desktop app (Windows/macOS/Linux) via NativePHP, with its own local SQLite database, full Fortify auth kept as-is, running alongside — not replacing — the existing Docker/web deployment.

**Architecture:** Add `nativephp/desktop` as a new dependency and route the one place the app currently writes outside Laravel's storage abstraction (company logo uploads, today via `public_path()`) through the same `Storage::disk('local')` pattern already used for estimation attachments — the only pattern NativePHP is documented to auto-persist correctly in a packaged build (it rewrites `storage_path()`/the `local` disk to the OS per-user appdata directory, but does **not** rewrite `public_path()`). Add a thin authenticated route to serve that logo back to the SPA and to the PDF templates. Configure `config/nativephp.php`, document and wire up build commands for all three platforms, and verify the Windows build end-to-end in this environment.

**Tech Stack:** `nativephp/desktop` (Electron-based), existing Laravel 13 / Inertia v3 / Vue 3 stack, SQLite (NativePHP-managed, no manual configuration).

**Spec:** [docs/superpowers/specs/2026-08-15-nativephp-desktop-design.md](../specs/2026-08-15-nativephp-desktop-design.md)

## Global Constraints

- Composer package is `nativephp/desktop` (the older `nativephp/electron` is archived) — requires PHP 8.3+ (this app runs PHP 8.5.1 ✓) and Laravel 11+ (this app runs 13.23 ✓); building installers requires Node 22+.
- NativePHP auto-creates and migrates a local SQLite database at `{appdata}/database/database.sqlite` and auto-rewrites `storage_path()`/the `local` filesystem disk to that same per-user appdata directory. No manual DB configuration is needed or should be added.
- NativePHP does **not** rewrite `public_path()`. Anything writing there via `public_path()`/`File::move()` will fail or silently not persist inside a packaged native build — must go through a `Storage` disk instead.
- Fortify (password, 2FA, passkeys) stays unchanged in both the web and desktop builds.
- The app currently dispatches no queued jobs anywhere (`grep -r ShouldQueue app` is empty) — no queue/worker configuration changes are needed for this plan.
- No auto-update in v1. No macOS/Linux installer is actually built in this environment (only the Windows build is executed and verified here) — those two are configured and documented, not run.
- The existing Docker/web deployment (`Dockerfile`, `docker-compose.yml`, `docker/entrypoint.sh`) must not change.

```markdown

## Desktop app (NativePHP)

Biglins can also run as a standalone desktop app (Windows/macOS/Linux) via
[NativePHP](https://nativephp.com/), independent of the Docker/web
deployment above. Each installation is single-user and keeps its own local
SQLite database — no server required.

```bash
composer require nativephp/desktop   # already in composer.json — only needed once
php artisan native:install           # already run for this repo; re-run after upgrading nativephp/desktop
php artisan native:run               # launch the desktop app in dev mode
```

NativePHP automatically creates and migrates a local SQLite database inside
the OS's per-user application-data directory on first run, and does the
same for anything stored on Laravel's `local` filesystem disk — no manual
database configuration needed.

### Building installers

```bash
php artisan native:build win     # produces a Windows installer
php artisan native:build mac     # produces a macOS .dmg — requires an Apple ID + team ID
                                  # and notarization, or other Macs will refuse to open it
php artisan native:build linux   # produces a Linux AppImage
```

Cross-compilation has limits: building Windows binaries from Linux needs
Wine with 32-bit support, and macOS builds must be signed/notarized on
Apple hardware to run on other Macs. `mac`/`linux` builds are not exercised
by this project's CI — only `win` is currently verified.

Auto-update is not configured; distribute new versions as new installers.
```
